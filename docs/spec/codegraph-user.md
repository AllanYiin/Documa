### 這個工具能做什麼

當你接手一個專案、準備修改共用功能，或想知道一項設計當初為什麼這樣做，可以在平常使用的 Codex 或 Claude Code 裡提問。Documa 會找出相關的程式、規格與測試，讓你能從答案點回原文核對。你也可以請助理把資料整理成專案導覽、變更摘要或說明文件。

整理答案和文件時，沿用你在助理裡已經能使用的功能，無須另外申請金鑰。支援邊產生邊顯示的聊天畫面會逐步呈現文字。你也可以在終端機查看固定格式的結果，例如檔案位置、原文節錄與變更清單。

### 你會怎麼使用它

| 你想做的事 | 怎麼操作與會拿到什麼 |
| --- | --- |
| 找功能入口 | 先選定專案並準備查詢資料，再問「Documa 如何選擇 PDF 讀取方式？」結果會帶你到負責選擇的程式位置，並列出可以核對的原文。 |
| 查設計依據與測試 | 問「這個行為寫在哪份規格？修改後要看哪些測試？」已找到明確出處時會附連結，只有間接線索時會標為待確認。 |
| 查原生程式 | 問「讀取 PDF 的功能從哪裡進入 Rust？」結果會顯示兩側能核對的程式位置。若某一段還無法確認，會指出缺在哪裡。 |
| 檢查變更影響 | 指定要比較的兩個版本，或比較目前尚未提交的修改。結果會列出受影響的公開功能、可能要重跑的測試，以及待核對的規格。 |
| 產出上手文件 | 請助理產出「從 PDF 入口讀到真正執行位置」的導覽。每一步標示出處，供新進成員循序閱讀。 |

### 提示語與復原方式

| 情境 | 訊息示例與下一步 |
| --- | --- |
| 正在更新 | 「正在更新專案的查詢資料。」更新完成後可重新提問。 |
| 查詢成功 | 「找到 PDF 讀取方式的選擇位置，已附上原文和相關測試。」可開啟來源核對。 |
| 專案剛被修改 | 「部分檔案已變更，請更新查詢資料後再試一次。」更新後可重問相同問題。 |
| 找不到確切依據 | 「找到相關程式，但目前的文件未說明這項決定的理由。」可指定一份本機規格再查。 |
| 查到部分結果 | 「目前可確認這幾段，另有部分關聯仍待確認。」可再問特定檔案、功能或版本。 |
| 找不到指定版本 | 「找不到要比較的版本。」可修正版本名稱，或改查工作中的修改。 |

### 完成後的結果與限制

你會得到能回到原文核對的答案、變更清單或導覽文件。專案修改後可以重新整理再接著查。長期不使用時，可以清掉為查詢建立的資料，日後重新建立。

候選測試是修改後可考慮重跑的清單，每筆會附推薦理由。部分程式要實際執行才能確定會走哪條路，這種情況在結果中會明示。回答可以引用已找到的設計紀錄，文件缺漏時會說出目前能確認的範圍。
